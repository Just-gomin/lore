# 7단계 작업 지시서: 비텍스트 추출기

로드맵 7단계를 어떤 순서로 만들지 정리한 문서입니다. 설계의 이유는 [기획서](plan.md)에 있고, 여기에는 순서와 완료 기준만 적습니다. 기획서와 이 문서가 다르면 기획서가 맞습니다. 이 문서가 기획서를 바꾸는 곳은 그 작업의 PR에서 기획서도 함께 고친다고 적었습니다.

이 문서는 4단계의 경고 운영, 5단계의 업무 프로젝트 적용, 6단계의 업무 프로젝트 확인이 끝나기 전에 썼습니다. 세 단계의 구현은 끝났고(v0.4.0), 남은 것은 실제 PR이 쌓이거나 사람과 함께 할 일입니다. 사람이 그 일을 하는 동안 이 단계를 먼저 진행하기로 했습니다. 앞 단계가 끝나면 그 결과를 반영해 이 문서를 갱신합니다.

## 목표

사람이 내보낸 이미지와 엑셀 파일을 추출기가 텍스트로 바꿔, 스킬이 정제해 소스 노트로 만들게 합니다.

기획서 8장의 7단계 완료 기준은 "회의 자료 하나가 소스 노트를 거쳐 결정에 연결됨"입니다. 앞 단계처럼 두 겹으로 나눕니다.

- **구현 완료**: 아래 작업 순서의 완료 기준을 모두 채웁니다.
- **단계 완료**: 진행 중인 프로젝트의 실제 회의 자료(화이트보드 사진, 회의에서 쓴 엑셀 등) 하나가 추출기와 `lore-source` 스킬을 거쳐 소스 노트가 되고, 그 노트를 근거로 한 결정이 `lore why <결정 ID> --depth source`에 나옵니다. 사람이 그 소스 노트의 정제 결과를 확인합니다. 블로그에는 회의 자료가 없어 업무 프로젝트에서 확인합니다.

## 범위

### 만드는 것

- 추출기 규약: 기획서 6장에 "커넥터 규약"과 나란히 "추출기 규약"을 적습니다.
- 설정의 `extractors`: 파일 확장자마다 쓸 추출기를 `lore.config.yaml`에 등록합니다.
- 추출기 세 개.
  - `lore-extractor-markdown`: 마크다운과 텍스트 파일
  - `lore-extractor-xlsx`: 엑셀(`.xlsx`, `.xls`)과 OpenDocument 스프레드시트(`.ods`)
  - `lore-extractor-image`: 이미지(`.png`, `.jpg`, `.jpeg`). 글자 인식은 외부 OCR 도구 tesseract를 부릅니다.
- `lore-source` 스킬: 파일을 받으면 등록된 추출기로 원문을 얻고, 그 원문을 정제합니다.

### 만들지 않는 것

- 녹음과 비디오의 전사. 가볍게 처리할 수 없어 필요를 느낄 때 진행합니다(사람이 정함). 이 단계의 1번 PR에서 기획서 8장 로드맵 7단계의 "비디오 추출기"를 빼고, 6장 확장 지점 표의 "나중에 추가"에 그대로 둡니다.
- PDF. 기획서 6장의 "나중에 추가"입니다.
- 추출기 안의 LLM. 요약과 정제는 스킬이 합니다(기획서 6장 구현 경계). 그림의 뜻(도표, 화살표)을 읽는 일도 스킬에 맡깁니다.
- 코어가 추출기를 부르는 일. 코어는 추출기를 실행하지 않습니다. 커넥터처럼 스킬이나 사람이 실행합니다.

## 공통 규칙

- 추출기는 lore 레포의 Cargo 워크스페이스 `extractors/` 아래에 두고 코어 바이너리와 함께 릴리스합니다. 코어 크레이트에는 의존하지 않고, 커넥터와 같은 후보 출력 형식을 `connectors/common`에서 가져다 씁니다. 릴리스 워크플로는 워크스페이스의 바이너리를 모두 묶으므로 새 바이너리도 자동으로 올라갑니다.
- 추출기는 네트워크를 쓰지 않고, 같은 파일과 같은 입력에는 같은 출력을 냅니다. 이미지 추출기는 tesseract의 판과 언어 데이터에 따라 결과가 달라질 수 있으므로, 출력에 쓴 tesseract 판을 남깁니다.
- 원본 파일은 레포에 넣지 않습니다(기획서 2장). 추출기는 파일 경로를 받아 읽기만 하고, 원본 링크(`origin`)는 부르는 쪽이 넘깁니다. 링크가 없는 파일은 스킬이 지정된 Drive 폴더에 올린 뒤 그 링크를 넘깁니다(지금의 `lore-source` 스킬과 같음).
- 새 의존 크레이트는 `Cargo.lock`으로 판을 고정합니다. 엑셀은 `calamine`, 이미지 메타데이터는 `kamadak-exif`를 씁니다. 해시는 커넥터와 같은 `sha2`입니다.
- 테스트는 고정 파일(`extractors/*/tests/fixtures/`)로 합니다. 이미지 추출기의 테스트는 tesseract 대신 정해진 글을 내는 가짜 실행 파일을 씁니다. 실제 tesseract로 하는 시험은 tesseract가 있을 때만 돌고, 없으면 건너뜁니다.

## 작업 순서

각 단계는 PR 하나입니다. 앞 단계가 병합된 뒤 다음으로 넘어갑니다.

### 1. 추출기 규약과 마크다운 추출기

- [ ] 기획서 6장에 "추출기 규약"을 적습니다.
  - **입력**: 표준 입력으로 JSON 하나를 받습니다. `file`(읽을 파일 경로), `channel`(채널 ID), `origin`(원본 링크)은 꼭 있어야 합니다. `kind`(기본 `reference`), `title`, `occurred_at`(`YYYY-MM-DD`)은 있으면 그대로 씁니다. 추출기마다 더 받는 항목(이미지의 `lang`)은 추출기가 정합니다. 모르는 항목은 오류입니다.
  - **출력**: 커넥터의 후보 출력과 같은 `{"ok": true, "candidates": [...]}`이고, 파일 하나에 후보 하나입니다. 그래서 스킬은 커넥터 후보와 같은 방법으로 정제합니다.
  - **원본의 판**: `origin_version`은 파일 내용의 sha256입니다. 같은 파일을 다시 넣으면 `lore add source`가 `unchanged`를 냅니다.
  - **제목과 날짜**: 입력에 없으면 파일에서 찾습니다(엑셀 문서 속성, 이미지 EXIF 촬영 시각, 마크다운 첫 `#` 제목). 제목은 마지막으로 파일 이름에서 확장자를 뺀 것을 씁니다. 날짜를 찾지 못하면 `occurred_at_missing` 오류로 끝나고, 부르는 쪽이 `occurred_at`을 넘겨 다시 부릅니다. 파일 수정 시각은 복사할 때마다 바뀌어 쓰지 않습니다.
  - **오류**: 커넥터와 같은 `{"ok": false, "error": {...}}`와 0이 아닌 종료 코드입니다.
- [ ] 기획서 5장 `lore.config` 파일 절에 `extractors`를 적고, `src/config.rs`가 읽게 합니다. 항목마다 `command`(실행 파일 이름)와 `extensions`(점 없는 소문자 확장자 목록)가 있습니다. 같은 확장자를 두 추출기에 적으면 설정 오류입니다. 코어는 형식만 검사하고 실행하지 않습니다.
- [ ] `lore install`이 만드는 기본 설정에 세 추출기를 등록합니다. 이미 있는 설정은 지금처럼 건드리지 않습니다.
- [ ] `lore-extractor-markdown`을 만듭니다. `.md`, `.markdown`, `.txt`를 받아 본문을 그대로 `text`로 냅니다. UTF-8이 아니면 `not_utf8` 오류입니다. 머리말이 있으면 떼어 내고 본문만 씁니다.
- [ ] 이 PR에서 기획서 8장 로드맵 7단계를 "이미지, 엑셀 추출기"로 고치고, 9장에 "비텍스트 추출기의 범위" 행을 더합니다(이미지는 외부 tesseract, 엑셀과 마크다운은 추출기 안에서, 녹음과 비디오는 필요를 느낄 때). `AGENTS.md`의 결정 수와 구조 표도 고칩니다.

완료 기준: 고정 마크다운 파일에서 기대한 후보가 나오고, 그 후보에 `slug`와 `body`를 더한 JSON이 `lore add source`를 통과합니다. 설정의 `extractors` 형식 오류가 `config_invalid`로 나옵니다.

### 2. 엑셀 추출기

- [ ] `lore-extractor-xlsx`를 만듭니다. 시트마다 `## <시트 이름>` 아래 마크다운 표로 냅니다. 첫 행을 머리글로 보고, 빈 행과 빈 열은 끝에서 잘라 냅니다. 셀 안의 `|`와 줄바꿈은 표가 깨지지 않게 바꿉니다.
- [ ] 날짜 셀은 `YYYY-MM-DD`(시각이 있으면 `YYYY-MM-DD HH:MM`), 수는 엑셀에 보이는 값에 가깝게 씁니다. 수식은 계산된 값을 씁니다.
- [ ] 제목은 문서 속성의 제목, 날짜는 문서 속성의 수정 시각(`dcterms:modified`)의 날짜를 씁니다.
- [ ] 큰 파일을 위해 시트마다 행 수에 상한(기본 500행)을 두고, 넘으면 잘라 내고 표 아래에 남은 행 수를 적습니다. 상한은 입력의 `max_rows`로 바꿉니다.

완료 기준: 시트 둘, 날짜와 수식, 병합 셀, 빈 행이 든 고정 파일에서 기대한 `text`가 나옵니다. 같은 파일을 두 번 넣으면 출력이 같습니다.

### 3. 이미지 추출기

- [ ] `lore-extractor-image`를 만듭니다. `tesseract <파일> stdout -l <언어>`를 부르고, 그 출력을 `text`로 씁니다. 언어는 입력의 `lang`, 없으면 `kor+eng`입니다. tesseract 실행 파일은 `PATH`에서 찾고, `LORE_TESSERACT` 환경 변수로 바꿀 수 있습니다.
- [ ] tesseract가 없으면 `tool_missing` 오류에 설치 방법을 적어 끝납니다. 언어 데이터가 없을 때의 tesseract 오류는 `tool_failed`로 감싸 냅니다.
- [ ] 날짜는 EXIF의 촬영 시각(`DateTimeOriginal`, 없으면 `DateTime`)을 씁니다. 스크린숏처럼 EXIF가 없으면 `occurred_at_missing`입니다.
- [ ] `text` 맨 위에 어떤 도구로 읽었는지(`tesseract <판>`, 언어) 한 줄을 남깁니다. 스킬이 인식 오류 가능성을 알고 정제하게 하기 위해서입니다. 인식한 글이 없으면 그 줄과 함께 "인식한 글자가 없습니다"를 냅니다.

완료 기준: 가짜 tesseract로 출력, 언어 인자, `tool_missing`, `tool_failed`, EXIF 날짜를 확인합니다. tesseract가 있는 환경에서는 고정 이미지(글자가 든 PNG)에서 그 글자가 나옵니다.

### 4. 스킬과 안내

- [ ] `lore-source` 스킬에 "파일을 받았을 때" 절을 더합니다. 확장자로 `extractors`에서 추출기를 찾아 입력 JSON을 표준 입력으로 넘기고, 후보의 `text`를 정제해 `body`를 씁니다. `occurred_at_missing`이면 사람에게 날짜를 묻습니다. 이미지는 에이전트가 그림을 직접 볼 수 있으면 인식한 글과 함께 보고 정제합니다. 등록된 추출기가 없는 형식은 지금처럼 에이전트가 직접 읽습니다.
- [ ] 민감도 규칙은 그대로입니다. `sensitive` 채널의 파일은 추출기도 부르지 않습니다. 추출기 출력에는 원문 전체가 들기 때문입니다.
- [ ] `tests/skills.rs`가 스킬의 명령 예시를 계속 해석하는지 확인합니다.

완료 기준: 고정 예제로 "엑셀 파일 → 추출기 → 입력 JSON → `lore add source` → 결정의 `--sources` → `lore why <결정> --depth source`"를 통합 테스트로 확인합니다(정제는 테스트가 정한 글로 대신합니다).

### 5. 릴리스

- [ ] 스킬과 기본 설정이 바뀌었으므로 버전을 올려 릴리스하고, 블로그에 다시 설치합니다. 블로그의 설정은 이미 있으므로 `extractors`는 손으로 더하지 않고, 필요할 때 사람이 더합니다.

완료 기준: 릴리스에 세 추출기의 바이너리가 두 플랫폼으로 올라가고, 내려받은 바이너리로 2번과 3번의 고정 파일에서 후보가 나옵니다.

## 정해야 할 것

- 여러 장으로 된 자료(사진 여러 장, 엑셀 여러 파일)를 소스 노트 하나로 묶을지. 지금은 파일 하나에 후보 하나이고, 묶는 일은 스킬이 여러 후보를 정제해 노트 하나를 쓰는 것으로 합니다. 이 경우 `origin`과 `origin_version`을 무엇으로 할지는 업무 프로젝트에서 실제 자료를 보고 정합니다.
